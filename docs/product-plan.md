# Free Rider 제품 기획 초안

상태: 기획 중
작성일: 2026-09-13

## 제품 방향

Bruno의 UI/UX와 작업 흐름을 참고하는 로컬 데스크톱 API 클라이언트. 핵심 가치는 OpenAPI 명세 변경을 diff로 검토하고, 선택해서 기존 컬렉션에 무료로 반영하는 것이다.

별도 서비스 서버나 클라우드 계정 없이 사용자 컴퓨터에서 실행·비교·저장한다. 사용자가 연결하는 OpenAPI URL과 Git 원격 저장소는 이용할 수 있다. 기기 간 설정 공유는 범위에 포함하지 않는다.

## 해결할 문제

명세가 변경될 때 API 요청을 수동으로 갱신하는 수고를 줄인다. 동시에 사용자가 작성한 요청값, 인증, 테스트가 명세 갱신 때문에 사라지지 않도록 한다.

## 첫 버전 범위

- 컬렉션·폴더·요청 탭을 통한 요청 작성 및 실행
- 환경변수, 인증, 응답 확인, 기본 검증
- 컬렉션에 OpenAPI 파일 또는 URL 연결
- 수동 동기화 버튼으로 명세 변경 확인
- 추가·수정·삭제된 API와 파라미터·본문·응답 스키마의 diff 표시
- 원하는 변경만 선택해 컬렉션에 반영
- 로컬 저장 및 기존 Git 저장소를 활용한 컬렉션 공유

Git 공유의 앱 내 지원 수준은 별도 결정한다. 자동 변경 감지는 이후 검토한다.

## 핵심 사용자 흐름

1. 컬렉션을 만들고 OpenAPI 파일 또는 URL을 연결한다.
2. 생성된 요청에 환경변수·인증·예시값·테스트를 작성하고 실행한다.
3. 동기화 버튼을 눌러 연결된 명세의 최신 내용을 읽는다.
4. 추가·수정·삭제 목록과 상세 diff를 검토한다.
5. 반영할 변경을 선택하고 충돌이 있으면 처리 방식을 선택한다.
6. 적용 결과를 확인하고 로컬에 저장한다.

## 변경 처리 원칙

- 명세 변경과 사용자 수정이 겹치지 않으면 사용자 수정을 보존하면서 선택한 변경을 반영한다.
- 명세 변경과 사용자 수정이 겹치면 자동 덮어쓰기를 하지 않는다. 양쪽 내용을 보여주고 사용자가 선택한다.
- 명세에서 삭제된 API는 바로 삭제하지 않고 삭제 후보로 표시한다.
- diff를 확인하는 것만으로 컬렉션을 변경하지 않는다.
- 요청값·인증·테스트 등 사용자가 작성한 내용을 보존한다.

## 첫 버전에서 제외

- 자체 서버, 클라우드 계정, 기기 간 설정 공유
- 실시간 공동 편집
- 명세 변경 자동 감지
- Bruno 전체 기능의 동등 구현

## 현재 저장소와의 관계

README 기준으로 요청 편집·실행, 환경변수, 인증, 검증, Git 저장·diff·commit 및 사용자 수정을 보존하는 OpenAPI 동기화 로직이 존재한다. 이는 문서상 현황이며 실제 동작과 위 요구사항의 충족 여부는 구현 검토 단계에서 확인한다.

## 다음 기획에서 결정할 사항

- diff 화면의 배치와 정보 구조
- 선택 반영의 최소 단위: API 단위 또는 필드 단위
- 충돌 표시 및 선택 방식
- 반영하지 않은 변경을 다음 동기화에서 처리하는 방식
- 응답 스키마 diff를 요청 문서에 반영하는 방식
- 적용 취소 및 복구 범위
- Git 공유의 앱 내 지원 수준

## 완료 기준 초안

- 명세의 API 추가·수정·삭제를 diff에서 구분할 수 있다.
- 적용 전에는 기존 컬렉션이 변경되지 않는다.
- 선택한 변경만 반영된다.
- 사용자가 수정한 요청값·인증·테스트가 의도치 않게 사라지지 않는다.
- 충돌은 사용자 선택 없이 덮어쓰지 않는다.
- 명세에서 제거된 API는 사용자 선택 없이 삭제되지 않는다.

## UI 검토 결과

- 광고성 헤드라인 없이 기능 중심의 제목과 설명을 사용한다.
- 변경된 endpoint를 단일 목록으로 표시한다.
- endpoint 행 또는 펼치기 버튼을 누르면 해당 행 아래 아코디언에 diff를 표시한다.
- endpoint 행에 변경 유형과 충돌 태그를 표시한다. 처리 방식을 선택한 충돌은 해결됨으로 구분한다.
- 체크박스로 API 단위의 반영 대상을 선택하는 방식을 유지한다.
- 선택한 API에 미해결 충돌이 있으면 반영을 차단한다.
- 삭제 후보는 기본 선택에서 제외한다.
- 검토용 시안: `docs/prototypes/sync-review.html`

UI 구성은 사용자 검토를 받았다. 현재 HTML은 예시 데이터로 동작하는 시안이며 실제 앱 구현은 별도 단계다.

## 전체 UI 시안 확장 — 검토 대기

동일 HTML 시안에서 사이드바와 상단 탭으로 세 화면을 전환한다.

- 요청 편집: URL·메서드, Params·Headers·Body·Auth·Tests를 제공한다. 응답 영역에는 본문·헤더·검증 결과를 표시한다.
- 명세 연결: URL 또는 로컬 파일을 선택하고 연결 확인 후 변경 검토로 진입한다.
- 동기화: 승인된 endpoint별 아코디언 diff·충돌 태그·선택 반영 구성을 유지한다.

시안의 요청 전송과 명세 연결은 예시 데이터 시뮬레이션이다. 앱 기능 구현, 실제 네트워크 요청, 파일 내용 읽기 및 영구 저장은 수행하지 않는다. 요청 입력은 화면 전환 중 유지되지만 새로고침 시 초기화된다. 이 확장 화면은 사용자 검토 전이다.

## Endpoint 테스트 UI — 검토 대기

- 요청의 Tests 탭에서 검증 대상·조건·예상값을 추가·수정·삭제한다.
- 고정 예시 응답을 대상으로 조건을 평가하고 실패 시 실제값과 예상값을 표시한다.
- 컬렉션 실행 화면에서 요청 선택, 순서 변경, 순차 실행, 실패 시 중단 및 수동 중지를 제공한다.
- endpoint 결과 행에서 성공·실패, 소요 시간 및 검증 상세를 확인한다.
- 시안의 컬렉션 결과는 고정 예시다. 로그인과 사용자 목록은 성공, 주문 목록은 검증 실패를 표시한다. 실제 토큰 추출이나 네트워크 요청은 수행하지 않는다.
