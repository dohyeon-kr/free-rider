LOCAL-FIRST API CLIENT

API 작업을 파일과 Git 가까이에.

Free Rider는 별도 서버와 계정 없이 요청 작성·실행, 환경별 변수, 전역 전후처리, 컬렉션 실행, OpenAPI 변경 검토와 선택 반영, 로컬 Git 작업을 제공하는 macOS Electron API 클라이언트입니다.

최신 버전 받기 문서 시작하기
Local-first워크스페이스를 암호화해 로컬에 저장하고 별도 서버·계정 없이 사용합니다.
OpenAPI review명세 변경을 먼저 검토하고 필요한 엔드포인트와 충돌만 선택해 반영합니다.
Git-friendly공유 가능한 컬렉션 파일만 diff·commit하고 로컬 비밀값은 제외합니다.

02

요청과 저장

컬렉션과 요청 만들기

사이드바의 +로 컬렉션을 만들고, 상단 + 요청 또는 탭의 +로 요청을 추가합니다. 컬렉션·폴더는 화살표로 접고 펼칠 수 있고, 컬렉션 제목 옆 화살표에서 현재 컬렉션을 바꿀 수 있습니다.

요청 편집

Params / Headers / Body / Auth / Vars / Tests / Docs에서 요청을 편집합니다. 단일 Send는 현재 편집 중인 내용을 사용하지만, 컬렉션 Runner는 저장된 요청을 사용합니다.

탭과 컬렉션 관리

탭을 닫을 때 변경이 있으면 저장·버리기·취소를 선택합니다. 탭 우클릭 메뉴에서는 현재 탭, 다른 탭, 저장된 탭 또는 모든 탭을 닫을 수 있습니다. 컬렉션 전체 삭제도 지원하며 마지막 컬렉션 하나는 유지합니다.

저장과 실행 로그

저장 버튼 또는 Cmd/Ctrl+S로 워크스페이스를 암호화해 로컬에 저장합니다. 전송 오류와 실행 로그는 응답 영역의 콘솔에 표시하며, Body에는 서버가 반환한 응답만 표시합니다.

HTTP 메서드

GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, QUERY와 사용자 정의 메서드를 입력할 수 있습니다.

CONNECT 터널과 TRACE/TRACK은 현재 전송 엔진에서 지원하지 않습니다.

03

Environment와 Vars

역할과 우선순위

종류용도스크립트 접근
Environmentdev/staging/prod처럼 실행 환경에 따라 바뀌는 읽기 전용 값.ctx.env.get("KEY")
Vars컬렉션·폴더·요청 범위 값과 실행 중 캡처한 런타임 값.ctx.vars.get/set/delete("KEY")

요청에서는 {{BASE_URL}}, {{accessToken}}처럼 사용하며 이름은 대소문자를 구분합니다.

변수 우선순위는 컬렉션·폴더 기본값 → 선택 Environment → 요청별 Vars → 실행 중 Vars 순입니다.

Auth 비밀번호와 환경 값처럼 마스킹된 입력은 눈 아이콘으로 표시/숨김을 전환할 수 있습니다.

.env 파일 연결과 편집

환경 화면에서 여러 환경을 만들거나 .env 파일을 연결할 수 있습니다. 연결된 파일은 원문을 직접 편집한 뒤 ‘편집 내용 적용’ 또는 ‘파일 저장’을 사용합니다.

‘다시 읽기’는 디스크의 최신 내용을 불러옵니다. 파일이 Free Rider 밖에서 변경되었다면 덮어쓰기를 막기 위해 저장이 차단되므로 먼저 다시 읽어 변경 내용을 확인해야 합니다.

환경 표는 현재 적용된 값을 확인하는 용도입니다. 파일 편집과 실제 적용 상태를 구분해 사용하세요.

04

전역 전후처리

모든 컬렉션에 적용

사이드바의 ‘전역 전후처리’에서 활성화합니다. 활성화된 전후처리는 모든 컬렉션에 적용되며, 컬렉션 실행을 시작할 때 설정을 고정합니다. 코드는 각 편집기에 함수 본문 형태로 작성하고 저장된 요청 원본은 직접 변경하지 않습니다.

전처리 예시

const token = ctx.vars.get("accessToken");
if (token) req.headers.set("Authorization", "Bearer " + token);
req.headers.set("X-Environment", ctx.env.get("ENV"));

후처리 예시

if (req.url.includes("/login") && res.status === 200) {
  ctx.vars.set("accessToken", res.json().accessToken);
}
ctx.log("HTTP", res.status);

제공 API

req.method, req.url, req.body, req.headers.get/set/delete

res.status, res.headers.get, res.text(), res.json()

ctx.env.get, ctx.vars.get/set/delete, ctx.log

런타임 값과 실행 제한

Environment 값은 읽기 전용입니다. 런타임 Vars는 같은 컬렉션·환경에서 이어서 사용할 수 있으며 앱 종료 또는 초기화 시 지워집니다.

스크립트에는 파일, 셸, 직접 네트워크 접근을 제공하지 않습니다. 별도 Worker의 QuickJS에서 시간·메모리 제한을 두고 실행합니다.

05

컬렉션 실행

‘엔드포인트 추가’로 저장된 요청을 실행 목록에 추가하고 원하는 순서로 배치합니다. 목록에서 요청을 제외해도 원본 요청은 삭제되지 않습니다.

선택한 요청의 연속 실행, 실패 시 중단, 수동 중지, 요청별 결과 확인을 지원합니다. 실행 목록 구성은 저장 버튼으로 보관합니다.

단일 Send는 현재 편집 중인 draft를 사용하지만, 컬렉션 Runner는 저장된 요청을 사용합니다.

06

OpenAPI 명세 동기화

  1. 1. 연결OpenAPI 3.x JSON/YAML 파일 또는 URL을 연결합니다.
  2. 2. 동기화변경 검토 목록을 생성합니다. 이 단계에서는 실제 요청을 변경하지 않습니다.
  3. 3. 비교엔드포인트를 펼쳐 이전 명세·현재 요청·새 명세를 비교합니다.
  4. 4. 충돌 해결현재 값 유지 또는 명세 값 반영을 선택합니다. 미해결 충돌이 남아 있으면 반영할 수 없습니다.
  5. 5. 선택 반영체크한 엔드포인트만 반영합니다. 삭제 후보는 기본적으로 선택하지 않습니다.
  6. 6. 저장과 복원저장이 성공한 뒤 변경을 적용하며, 직전 반영 상태는 복원할 수 있습니다.

변경 검토 규칙

선택하지 않은 변경은 다음 동기화에서도 계속 남습니다. Headers·Query·응답 스키마는 항목별로 비교하고, 문자열 Body와 배열은 하나의 값으로 비교합니다.

외부 $ref가 있는 명세는 먼저 bundle한 뒤 가져옵니다. 연결한 파일을 디스크에서 수정했다면 ‘다시 읽기’로 최신 상태를 불러와 재검토할 수 있습니다.

서버 주소와 baseUrl

선택한 환경의 baseUrl이 비어 있으면 명세의 서버 주소 등록을 제안합니다. URL로 연결한 명세의 상대 서버 주소는 명세 URL을 기준으로 해석합니다.

07

Git 공유

컬렉션만 안전하게 커밋

로컬 Git 저장소를 선택하고 컬렉션 파일 저장 → diff 확인 → commit 순서로 사용합니다. Free Rider는 open-api.collection.json만 커밋하므로 다른 staged 파일은 포함하지 않습니다.

최근 컬렉션 관련 커밋을 앱 안에서 확인할 수 있습니다. Push/Pull은 Free Rider가 직접 수행하지 않으며 외부 Git 클라이언트를 사용합니다.

공유 파일에 포함되는 것

환경의 실제 값, 연결한 로컬 파일 경로, 전역 스크립트, 복원 백업은 공유 컬렉션 파일에 포함하지 않습니다.

요청에 직접 입력한 값은 컬렉션에 포함됩니다. 팀과 공유할 값이나 비밀값은 요청에 하드코딩하지 말고 변수로 작성하세요.

08

자동 업데이트

배포용 macOS 앱은 Electron 공식 update.electronjs.org와 GitHub Releases를 사용합니다. 앱은 현재 아키텍처(darwin-arm64 또는 darwin-x64)에 맞는 새 버전을 확인하고 백그라운드에서 내려받습니다.

macOS Squirrel 자동 업데이트에는 Developer ID 서명이 필요하므로 ad-hoc/개발 빌드에서는 자동 업데이트를 비활성화합니다. 새 버전 다운로드가 끝나면 앱 하단에서 설치 및 재시작할 수 있습니다.

09

개발·검증과 문서 배포

검증과 macOS 빌드

npm test
npm run test:electron
npm run dist:mac -- --config.mac.identity=null

Electron smoke test는 임시 파일·임시 저장소·HTTP 서버를 사용하므로 사용자의 실제 워크스페이스를 사용하지 않습니다. 화면 캡처는 test-results/에 생성됩니다.

GitHub Pages

docs/site/의 정적 문서는 .github/workflows/docs.yml에서 gh-pages 브랜치로 배포합니다.

GitHub Pages 저장소 설정에서 Source를 Deploy from a branch, Branch를 gh-pages / (root)로 한 번 설정하면 이후 문서 변경이 자동 반영됩니다.

구현 및 검증 기록은 저장소의 docs/implementation-plan.md, docs/completion-audit.md에서 확인할 수 있습니다.
