# Free Rider Electron 구현 계획

작성일: 2026-09-13
상태: 구현 착수 기준안. 이 문서 작성 단계에서는 앱 코드를 변경하지 않았다.

## 목표와 화면 기준

검토한 docs/prototypes/sync-review.html의 어두운 색상, 사이드바, 탭, 요청 편집기와 각 기능 화면을 실제 Electron 앱으로 옮긴다. 새 디자인으로 재설계하지 않는다. 시안의 고정 데이터·시뮬레이션만 실제 상태와 기능으로 교체한다.

별도 서비스 서버와 계정은 없다. 요청 대상 API, 명세 URL, 사용자가 연결한 로컬 Git 저장소를 이용한다. 기기 간 설정 공유와 앱 내 Push/Pull은 첫 버전에서 제외한다.

유지할 기능:
- 컬렉션·폴더 접기/펼치기, 요청 생성·수정·삭제, 여러 요청 탭과 닫기
- Params / Headers / Body / Auth / Tests, 응답 본문·헤더·검증 결과
- OPTIONS·QUERY를 포함한 메서드 선택과 직접 입력
- 명세 파일·URL 연결, endpoint별 아코디언 diff와 충돌 태그, 선택 반영
- 컬렉션 실행의 엔드포인트 추가·제외·순서 변경
- .env 환경 선택과 {{VARIABLE}}, 전역 req/res 전후처리
- Git 저장소 연결·파일 저장·diff·commit·최근 커밋

## 코드 조사 결과

아래는 소스 확인 결과이며 실제 실행 검증 완료를 뜻하지 않는다.

| 영역 | 현재 코드 | 구현할 차이 |
| --- | --- | --- |
| Electron | main.cjs / preload.cjs, 격리된 렌더러와 IPC | 시안 이식, IPC 입력 검증과 실행별 상태 |
| UI | ui/app.js에 탭·트리·요청·실행 화면 존재 | 시안 배치 적용, 화면별 모듈 분리, draft 분리 |
| 저장 | WorkspaceStore의 암호화·직렬 쓰기·임시 파일 교체 | 버전 마이그레이션, 재시작 복원, 오류 복구 |
| 요청 | HTTP fetch, 치환·인증·취소·검증 | QUERY 등 메서드, 전후처리와 공통 실행 경로 |
| 환경 | dotenv 파싱, 환경별 런타임 값 분리 | 파일별 연결·재읽기·편집 저장, 우선순위 통일 |
| 명세 | OpenAPI 3.x 파싱, 내부 참조, baseline 보존 병합 | 응답 스키마 보관, 3-way diff, 충돌 선택·부분 반영 |
| 실행 목록 | 선택된 저장 요청을 순차 실행 | 별도 실행 목록 저장, 추가·제외·순서와 실행 스냅샷 |
| Git | 로컬 연결·상태·저장·diff·파일 한정 commit | 최근 이력, 최초 커밋·미추적 파일·오류 처리 |
| 테스트 | core/workflow/git/curl 및 Electron smoke | 새 계약과 실제 UI 회귀 검증 |

현재 synchronize는 사용자 수정 필드를 보존하며 전체 결과를 병합한다. 사용자가 검토한 endpoint 선택·충돌 해결 계약을 구현한 상태는 아니다.
현재 요청 준비 코드에는 메서드 허용 목록이 있으며 QUERY를 거부한다. fetch 기반 전송 자체에도 메서드 제약이 있으므로 목록만 늘려서 완료로 처리하지 않는다.
명세 파서는 응답 스키마를 요청 모델에 보관하지 않는다. 응답 스키마 diff를 위해 정규화 모델 확장이 필요하다.

## 구현 구조

기존 Electron + JavaScript를 유지한다. 이번 이식에서 React 등 별도 프레임워크 전환을 함께 진행하지 않는다.

- Renderer: 시안의 화면·입력·탭·draft·실행 결과 표시. 파일이나 Git에 직접 접근하지 않는다.
- Preload: 기능별 좁은 API와 실행 진행 이벤트. 임의 IPC 채널이나 셸 실행을 노출하지 않는다.
- Main: 파일 선택·저장, 환경 로딩, 네트워크 실행, 명세 검토·반영, Git 작업을 담당한다.
- 전후처리 실행기: UI와 main을 멈추지 않도록 별도 실행 경계에서 동작하며 종료 시간과 취소를 제공한다.

ui/app.js의 화면을 shell, request, sync, runner, environments, scripts, git 모듈로 나눈다. 시안 HTML의 전역 변수나 inline onclick을 그대로 앱 상태로 사용하지 않는다. 기존 modules/env, workspace, git, runner는 확장하고 sync는 preview/apply 계약으로 분리한다.

## 상태와 저장 계약

- Workspace: 컬렉션 목록, 전역 전후처리, 로컬 환경 연결, 열린 탭·선택·접힘 상태.
- Collection: 안정적인 ID, 폴더, 저장된 요청, 명세 연결, 실행 목록.
- Request: 안정적인 ID, 메서드·URL·입력 행·본문·인증·검증, 명세 식별자와 baseline.
- Draft: 저장된 요청과 분리한 편집본. 탭 닫을 때 저장/버리기/취소.
- RunPlan: requestId 순서와 선택 상태. 제외해도 원본 요청은 남는다. 원본 삭제 시 목록 참조도 정리한다.
- Execution: 실행 시작 시 요청·환경·스크립트 스냅샷, 실행 ID, 진행·결과. 실행 도중 설정 변경은 다음 실행부터 반영한다.

기존 version 1 컬렉션은 version 2 모델로 마이그레이션하고 변환 전 백업을 보관한다. 환경 실값과 실행 중 변수는 Git 내보내기 대상에서 제외한다. 전역 설정·로컬 경로도 컬렉션 공유 파일에서 제외한다. 요청·검증·실행 목록·명세 baseline은 공유 가능한 컬렉션 데이터로 저장한다.

## 요청·환경·전후처리 계약

변수 우선순위는 기본 컬렉션 값 < 선택한 .env 값 < endpoint별 변수 < 현재 실행의 런타임 값으로 한다. 기존 폴더 변수는 컬렉션 값과 .env 값 사이에 둔다. 우선순위를 UI 도움말에 표시한다.

.env.local, .env.dev 등 이름을 고정하지 않고 파일을 여러 개 연결한다. 선택 환경만 사용하고 파일들을 암묵적으로 합치지 않는다. 파일 재읽기와 저장은 명시적으로 제공하며 수정 중 외부 변경은 덮어쓰기 전에 비교한다. 누락된 변수는 전송 전 위치와 이름을 표시한다.

실행 순서:
1. 저장 요청 또는 현재 draft의 실행 복사본을 만든다.
2. 선택 환경과 런타임 값을 이용해 URL·Params·Headers·Body·인증을 치환한다.
3. 모든 요청에 전역 beforeRequest(req, ctx)를 실행한다.
4. 변경된 요청을 검증하고 전송한다.
5. 전역 afterResponse(res, ctx)를 실행한다.
6. 검증을 평가하고 결과를 저장한다.

전역은 워크스페이스의 모든 단일 요청과 컬렉션 실행에 적용된다는 의미다. req 수정은 해당 전송 데이터에 반영되고 저장된 요청 템플릿은 유지한다.

제안 API:
- req.method, req.url, req.headers.get/set/delete, req.body
- res.status, res.headers.get, res.text(), res.json(): 응답은 읽기 전용
- ctx.env.get(name): 선택 환경 읽기
- ctx.vars.get/set/delete: 실행 중 값 읽기·갱신
- ctx.log(...): 실행 상세에 로그 표시

토큰 추출은 ctx.vars.set("accessToken", res.json().accessToken) 같은 일반 후처리로 구현한다. 컬렉션 실행에서는 다음 요청에 변수를 전달한다. 단일 실행에서는 같은 컬렉션·환경 세션에 유지하고 초기화 버튼을 둔다. .env 파일에 자동 기록하지 않는다.

스크립트는 파일·셸·직접 네트워크 API를 제공하지 않는다. 단순 node:vm을 보안 경계로 간주하지 않는다. 제한 API를 제공할 격리 런타임을 짧은 기술 검증으로 선정하고 무한 루프·취소·비동기 완료를 확인한 뒤 연결한다. 전처리 실패는 전송하지 않고, 후처리 실패는 수신 응답을 남긴 채 단계 오류로 표시한다. 첫 버전은 순차 실행을 기준으로 한다.

메서드는 문자열로 보관하고 HTTP token 문법으로 검사한다. QUERY는 본문 전송까지 로컬 서버로 검증한다. TRACE와 CONNECT는 실제 전송 계층의 제약을 검증하고 지원 상태를 UI에 반영한다. CONNECT 터널 기능은 일반 요청 전송과 별도이며 초기 완료를 위해 구현하지 않는다. OpenAPI의 인식 가능한 메서드와 수동 요청의 메서드를 별도 취급한다.

## 명세 diff와 선택 반영

baseline(마지막 반영 명세), local(현재 요청), incoming(새 명세)을 비교한다.
- 명세만 바뀐 필드는 반영 후보, 사용자만 바꾼 필드는 보존.
- 양쪽이 다르게 바뀐 필드는 충돌, 동일 값이면 충돌 아님.
- endpoint 행에서 선택하고 아코디언 내부에서 필드별 현재 값/명세 값을 결정.
- 미해결 충돌이 있는 선택 항목은 반영 불가. 삭제는 기본 미선택.
- 미선택 endpoint의 baseline은 갱신하지 않아 다음 검토에서도 변경이 남는다.
- 선택 endpoint는 충돌 해결 결과와 incoming baseline을 함께 저장한다.
- 검토 후 요청이 다시 수정되면 revision 비교로 오래된 검토 적용을 막고 재검토한다.
- 반영은 한 번의 저장으로 처리하고 저장 실패 시 기존 상태 유지. 직전 반영 백업으로 복원 제공.

명세가 제공한 파라미터·본문·응답 스키마를 정규화해서 비교한다. 첫 버전의 외부 $ref 제한은 유지하고 지원하지 않는 명세는 구체적으로 표시한다. path/method 변경은 기본적으로 삭제+추가이며 자동 이름 변경 추론은 하지 않는다. 수동 요청은 명세 삭제 후보에서 제외한다.

## 단계별 구현과 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 0. 실행 기준 확보 | 의존성 설치, 기존 테스트·Electron smoke, 로컬 API fixture, 데이터 모델·IPC 계약 확정, 메서드/스크립트 기술 검증 | 기존 동작과 실패 목록 기록, 확장 메서드 및 격리 방식 결정 |
| 1. 시안 이식 + 실제 요청 | 시안 스타일·레이아웃, 트리·탭·draft, 요청 편집/저장/전송/취소, 응답 표시 | 시안 배치에서 실제 endpoint 작성·전송·저장·재시작 복원, 탭 버리기 검증 |
| 2. 환경 + 전역 처리 | 여러 .env 연결, 치환, 전역 전후처리, 로그·단계 오류 | 환경별 다른 API 호출, 전처리 헤더 적용, 후처리 값 다음 요청 전달, 환경 간 값 격리 |
| 3. 컬렉션 실행 | endpoint 추가·제외·순서 저장, 실행 진행, 중단, 검증 결과 | 로그인→조회 흐름이 실제 동작, 실패 시 중단과 수동 취소, 원본 요청 보존 |
| 4. 명세 연결·선택 반영 | 파일/URL 재읽기, 정규화, 3-way diff, 충돌·삭제 선택, 복원 | 미선택 변경 유지, 사용자 값 보존, 충돌 차단, 재시작 후 baseline 유지 |
| 5. Git 화면 연결 | 실제 저장소 상태·diff·commit·최근 이력, 최초 커밋 대응 | 컬렉션 파일만 commit, 다른 staged 파일 유지, 환경 실값 제외 |
| 6. 통합·패키징 | 빈 상태·오류·키보드·창 크기 점검, macOS 패키지 설치 실행 | 설치본에서 작성→실행→명세 반영→Git commit→재실행까지 통과 |

각 단계마다 Electron 앱에서 검토할 수 있는 상태로 마무리한다. 단계 1이 첫 실제 앱 리뷰 지점이다. 서명·공증은 배포 인증정보 준비 여부에 따라 별도 배포 작업으로 구분한다.

## 검증 계획

- Node 테스트: 모델 마이그레이션, 변수 우선순위, QUERY 본문, 검증, 스크립트 시간초과, 동기화 충돌·부분 baseline·삭제.
- 로컬 HTTP fixture: 실제 요청 메서드/헤더/본문 확인, 오류·지연·취소·응답 처리, 전역 전후처리와 연속 실행.
- 임시 Git 저장소: 최초 commit·미추적 diff·변경 없음·다른 staged 파일 보존.
- Electron: 탭 저장/버리기/취소, 컬렉션 접힘, 실행 추가·순서·중단, 충돌 선택, 재시작 복원.
- 시안과 실제 화면 비교: 같은 창 크기에서 화면별 배치·색·밀도·스크롤·빈 상태 검토.

현재 단계에서는 소스 조사만 수행했다. 기존 테스트 실행, 실제 Electron 화면 확인, 새 기능 구현은 단계 0부터 진행한다.

## 구현 진행 — 2026-09-13

첫 실행본:
- Electron 런타임 설치 및 기존 16개 테스트 통과.
- Free Rider 이름, 시안의 색상·탭·사이드바·요청 편집 배치 적용.
- 메서드 직접 입력과 QUERY 추가. 실제 로컬 서버에서 QUERY 본문·헤더 수신 확인.
- fetch가 지원하지 않는 TRACE/CONNECT/TRACK은 명확한 오류로 표시.
- 명시적 워크스페이스 저장 시 컬렉션·폴더 접힘 상태 저장 및 로딩.
- 새 테스트 포함 18개 통과. Electron smoke에서 로그인 연속 실행·인증·검증·환경·cURL 입력·탭 닫기 통과.
- Electron 요청 화면 캡처 확인.

단계 1은 진행 중이다. 요청별 draft 저장/버리기/취소, 전체 화면의 시안 이식과 재시작 통합 검증은 남아 있다. 전역 Scripts, 선택 동기화와 실행 목록 확장은 아직 구현하지 않았다.

### 요청 draft 처리

- 요청 편집본을 별도 RequestDrafts로 분리했다.
- 단일 전송은 편집본, 컬렉션 실행은 저장된 요청을 사용한다.
- 탭 닫기에서 저장하고 닫기 / 버리고 닫기 / 취소를 제공한다.
- 파일 저장 성공 후 저장 모델에 반영하며, 실패 시 편집본을 유지한다.
- 전체 저장은 모든 요청 편집본을 반영한다.
- 단위 테스트 19개와 Electron 저장·버리기·취소·재열기 검증 통과.
- 나머지 화면 이식과 재시작 통합 검증은 아직 진행 대상이다.

### 명세 선택 반영 구현
- 파일·URL 동기화를 검토 후 선택 반영으로 변경했다.
- endpoint 아코디언에서 이전 명세·현재 요청·새 명세를 비교한다.
- 충돌 필드의 현재 값 유지/명세 값 반영을 결정하기 전에는 선택 반영을 차단한다.
- 삭제는 기본 미선택, 수동 요청은 삭제 후보에서 제외한다.
- 미선택 endpoint의 baseline은 유지한다. 검토 후 요청 변경 또는 선택 요청의 미저장 draft가 있으면 재검토를 요구한다.
- 응답 스키마를 비교 모델에 포함했다.
- 반영 결과는 기존 저장 버튼으로 보관한다. 자동 디스크 저장 및 직전 반영 복원 기능은 아직 없다.
- 핵심 비교 단위는 요청의 최상위 필드(예: headers, query, body)이며 중첩 필드의 세밀한 병합은 후속 개선 대상이다.
- Electron에서 URL 명세 검토 전 원본 유지와 선택 반영 후 요청 추가를 검증했다.
